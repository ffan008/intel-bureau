# 飞书接入指南

飞书通过官方命令行工具 **lark-cli**（npm 包 `@larksuite/cli`）接入。读消息有两种身份：

| 身份 | 能读哪些群 | 需要做什么 |
|---|---|---|
| **用户身份（推荐）** | 你本人所在的全部群 | 在终端运行一次 `lark-cli auth login` 授权 |
| 机器人身份 | 只有机器人被拉进去的群 | 把应用机器人拉进要监控的群 |

## 一、安装 lark-cli

> **分享包用户**：lark-cli 已经随包带好，**不用运行下面的下载命令**。
> Windows 双击「安装接入工具.bat」选 3；**macOS 什么都不用做**，随包工具直接用。
> 下面的命令只在你想联网更新到最新版时才需要。

lark-cli 的命令在两种系统上写法不同（下文的 `<lark-cli>` 都指它）：

| 系统 | 命令 |
|---|---|
| Windows | `third_party\tools\lark-cli\node_modules\@larksuite\cli\bin\lark-cli.exe` |
| macOS | `third_party/tools/lark-cli/node_modules/.bin/lark-cli`（要先装 Node.js：`brew install node`） |

> macOS 上更省事：**双击根目录的「飞书重新授权.command」**，它会自己找 lark-cli、打开授权页、
> 等你在浏览器里点完授权、再顺手让工作台重新测一次连接。下面第二节的命令是它的手动版，效果一样。

在项目根目录打开 PowerShell，运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\tools\get-lark-cli.ps1
```

脚本会把 lark-cli 1.0.98 装到 `third_party\tools\lark-cli\`，并打印当前登录状态。
（如果你电脑上已经有 lark-cli，工作台也能自动找到。查找顺序：设置里填的路径 → PATH →
`third_party\tools\lark-cli` → WorkBuddy 自带的 lark-cli。）

第一次使用、还没有配置飞书应用时，运行：

```powershell
third_party\tools\lark-cli\node_modules\@larksuite\cli\bin\lark-cli.exe config init
```

按提示完成。已经配置过（例如用过 WorkBuddy 的飞书功能）就跳过这一步。

## 二、方式 A：授权用户身份（推荐）

1. 在终端运行（`<lark-cli>` 按第一节的表格替换成你系统上的路径；macOS 也可以直接双击「飞书重新授权.command」）：
   ```bash
   <lark-cli> auth login --domain im
   ```
   - `--domain im` 只申请消息和群相关的权限；不加参数会申请全部业务的权限。
   - 想同时把风向标写进飞书知识库（见「六、飞书知识库树」），改成 `--domain im,docs,wiki`；
     只写单篇云文档时 `--domain im,docs` 就够。
2. 浏览器会打开飞书授权页，用**你本人的账号**确认授权。
3. 回到终端，运行下面的命令确认「用户身份」显示 ready：
   ```bash
   <lark-cli> auth status
   ```

   macOS 也可以 `bash scripts/feishu-reauth.sh --status`，它会顺带打印「授权最迟有效到」的时间。
4. 两种「过期」，含义不同：
   - **访问令牌到期**（2 小时）：lark-cli 会自动续期，**不用管**。工作台会显示「令牌已到期，读取时会自动刷新」。
   - **刷新令牌到期**（7 天没用过就失效）：这才是真的要重新授权，重复第 1 步即可。

## 三、方式 B：把机器人拉进群

1. 在飞书里打开要监控的群 → 群设置 →「群机器人」→「添加机器人」→ 选择你的应用机器人。
2. 每个要监控的群都要拉一次。
3. 应用需要在飞书开发者后台开通读取群消息的权限（如 `im:message.group_msg`、`im:chat:read`）。
   权限不够时，工作台会提示缺哪些权限。

## 四、在工作台里配置

1. 工作台 →「情报源」→ 飞书，适配器选 **飞书官方 lark-cli**。
2. 「读取身份」选「用户身份」或「机器人身份」；「lark-cli 路径」一般留空。
3. 点「测试」：

   | 提示 | 怎么办 |
   |---|---|
   | lark-cli 用户身份可用 | 完成 |
   | 用户身份可用（令牌已到期，读取时会自动刷新） | 正常，不用处理 |
   | 用户授权已过期 / 未登录 | 在终端运行 `<lark-cli> auth login` 重新授权（macOS 双击「飞书重新授权.command」） |
   | 机器人身份可用，但机器人不在任何群里 | 把机器人拉进要监控的群，或改用用户身份 |
   | 没有找到 lark-cli | 回到第一步安装 |
   | 缺少权限：… | 用户身份：按提示运行 `lark-cli auth login --scope "…"`；机器人身份：到开发者后台开通 |

4. 点「刷新群列表」，把要监控的群加入白名单。

说明：lark-cli 返回的消息时间只精确到分钟，工作台会把每个窗口起点所在的那一分钟也取回来，
重复的消息按消息 ID 去重。

## 五、日报推送到飞书

两种方式可以同时用：

### 方式 1：机器人私聊你（「飞书应用机器人（lark-cli）」通道）

1. 查你自己的 open_id：运行 `lark-cli auth status`，看用户身份里的 `openId`（`ou_` 开头）。
   如果用户身份没有授权，也可以在飞书开发者后台「API 调试台」里查。
2. 确认你在应用的「可用范围」内（开发者后台 → 应用发布 → 可用范围）。
3. 工作台 →「推送」→ 新增「飞书应用机器人（lark-cli）」：
   - 发送到：私聊某人（open_id）
   - 接收方 ID：你的 `ou_…`
   想发到群就选「群聊」，填 `oc_…`（机器人要先在群里；群 ID 可用 `lark-cli im +chat-search --query 群名` 查）。
4. 点「发送测试」。

### 方式 2：群 Webhook（「飞书群机器人（Webhook）」通道）

不需要应用权限，适合发到某个群：

1. 飞书群 → 群设置 →「群机器人」→「添加机器人」→「自定义机器人」。
2. 安全设置里选「签名校验」，复制密钥。（如果选「自定义关键词」，请加入关键词「情报局」。）
3. 复制 Webhook 地址。
4. 工作台 →「推送」→ 新增「飞书群机器人（Webhook）」，填 Webhook 地址和签名密钥，点「发送测试」。

## 六、飞书知识库树（「飞书文档 / 知识库」通道）

这个通道把每天的风向标写进飞书。它有两种写入方式（设置项「写入方式」）。

### 两种模式

**知识库树（`wiki`，默认）**：按天组织成一棵树。

```
情报局知识库                      ← 知识空间
└─ 每日风向标                     ← 节点
   └─ 2026-10-30（今日风向标）    ← 当天总览：今日总览 + 专题目录（带直达链接）+ 资源库 + 快讯
      ├─ 01-{专题标题}            ← 每篇专题一篇子文档，正文是完整的专题文章
      ├─ 02-{专题标题}
      └─ …
```

- 写入顺序：空间 → 「每日风向标」→ 当天总览页（先写初稿）→ 各篇专题 → 用带专题链接的终稿覆盖总览页。
- 专题里的图片尽力插入到文末的「图片」小节，每篇最多 6 张。插入失败时写一行「图片见工作台」。
- 中途失败（比如网络断了）时，再次投递只补建没完成的部分，不会重复建文档。每一步的结果按报告 ID
  记在 `data/cache/feishu_wiki.json`。
- 同一天如果有第二份报告，总览页标题会加上「（第 2 版）」。
- 投递结果里的链接是当天总览页。工作台会把它放进推送消息，飞书私聊消息末尾也会多一行「👉 查看今日风向标」。

**单篇文档（`single`）**：v1 的做法，整份报告写成一篇云文档，投递结果里带文档链接。
以前在「父文件夹 / 知识库节点 token」或「父节点位置」里填过值、又没有选写入方式的通道，
会继续按单篇文档写，行为不变。想改用知识库树，把写入方式改成「知识库树」即可。

### 知识空间会自动创建

「知识空间 ID」留空时，通道会先找你能访问的、名字叫「情报局知识库」的空间：

- 找到了就直接用。
- 找不到就新建一个（只有**用户身份**能建空间）。
- 用到的 space_id 记在 `data/cache/feishu_wiki.json`，以后不再查找。

「每日风向标」节点同理：没有就新建，有同名节点就复用。

### 指定已有的空间或页面

- **知识空间 ID**：填纯数字的 space_id。可以在终端运行 `lark-cli wiki +space-list --as user` 查看，
  也可以在空间的设置页地址里找到。
- **「每日风向标」节点**：想把每天的页面放到某个已有页面下面，就填这个页面的知识库链接
  （`https://xxx.feishu.cn/wiki/...`）或 node_token。填了它就不需要再填空间 ID。
- **飞书网页地址**（可选）：如 `https://xxx.feishu.cn`，用来生成知识库页面链接；
  留空时会从飞书返回的文档链接里自动识别。

### 需要的权限

你之前已经授权过 `im` 和 `docs` 两类权限。知识库树还需要 **wiki** 权限，在终端补一次授权：

```powershell
lark-cli auth login --domain im,docs,wiki
```

用到的接口和权限：

| 操作 | 命令 | 权限 |
|---|---|---|
| 查找知识空间 | `wiki +space-list` | `wiki:space:retrieve`（或 `wiki:wiki:readonly`） |
| 新建知识空间（仅用户身份） | `wiki +space-create` | `wiki:space:write_only`（或 `wiki:wiki`） |
| 查找 / 新建「每日风向标」节点 | `wiki +node-list`、`wiki +node-create` | `wiki:node:retrieve`、`wiki:node:create` |
| 查询节点 | `wiki +node-get` | `wiki:node:read` |
| 新建总览页和专题文档 | `docs +create --parent-token <节点>` | `docs` 授权里的建文档权限（如 `docx:document:create`） |
| 更新总览页、插入图片 | `docs +update --command overwrite / append` | `docs` 授权里的编辑和上传素材权限 |

缺权限时，投递结果会写出缺的是哪一项，并提示补授权的命令。

**用机器人身份**：机器人不能新建知识空间，所以必须填「知识空间 ID」，并且要先在飞书里把应用加为
该空间的成员（有编辑权限），再到开发者后台给应用开通上表的权限。推荐用用户身份，页面直接归你所有。

### 配好以后

在工作台「推送」里点这个通道的「发送测试」：会在「每日风向标」下建一页「通道测试 {时间}」，
确认能打开以后可以手动删掉。

已知限制：

- 图片统一放在每篇专题的末尾，不会插到正文中间。
- 总览页里单个板块超过 4 万字时会截断，并附上工作台链接。
- 「每日风向标」下每天新增一页，一年后子页面会很多；如果飞书提示节点数量超限（错误码 131003），
  请在设置里换一个「每日风向标」节点。
